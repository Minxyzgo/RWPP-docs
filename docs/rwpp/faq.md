# 常见问题

## 扩展应该放在哪里

桌面端放在游戏目录下的 `extensions/`，与替换后的 `game-lib.jar` 同级。Android 放在 `/storage/emulated/0/rustedWarfare/extensions`。扩展不是模组，不要放进模组目录。

## 启动器提示存在多个版本

同一标识安装了多个归档，宿主不会自行猜测。打开扩展管理页，为每个冲突标识选择版本后重启。选定结果记录在 `data/extension-state.properties`。

## 提示重复标识

同一标识的两个归档内容不同，且版本相同。保留需要的那个，删除或移除另一个。游戏运行期间不能替换已加载的归档，需要先关闭游戏。

## 装了 RWPP 但界面没有变化

确认扩展页同时列出 `io.github.rwpp.api` 与 `io.github.rwpp`，且两个版本来自同一发布。只有客户端没有 API 时，客户端会因为缺少依赖而失败。

## 启动卡在加载界面

先看启动器输出的最后几行。常见原因是扩展依赖缺失、mixin 目标类不匹配，或游戏版本与映射版本不一致。失败扩展会在日志中列出标识与原因。

## 画面黑屏、闪烁或抖动

在设置中切换渲染后端后重启。部分显卡驱动对 OpenGL 路径更敏感，切换到默认后端可以排除渲染问题。

## 启动器找不到游戏

RWML 与 RWPP 必须位于游戏本体目录。把发行包解压到其他位置时，启动器无法定位 `game-lib.jar` 与 `assets/`。

## 更新后版本号没有变化

扩展在下一个进程加载。安装完成后需要完全退出并重新启动，已加载的归档不会被运行中的进程替换。

## Android 无法读取扩展

首次启动需要授予存储访问权限。拒绝后可以在系统设置中重新授权，再启动一次。扩展目录变化后，第一次启动会重建 dex 缓存，耗时略长。

## 首次启动直接进入原版游戏

先查看游戏目录下的 `data/rwml-bootstrap.log`。安装程序会把 Java 25 放在 `rwml-runtime`；该目录缺失时重新运行安装程序。只替换了 `game-lib.jar` 时，启动器需要联网获取 Java 25，网络失败会继续以原版启动。

## Android 如何安装扩展

从启动器或扩展管理页进入“浏览”，搜索目录后安装或更新；也可以在扩展管理页导入整合包。安装完成后完全退出并重新启动。

## 模组传输不可用

模组传输只对自行创建或托管的房间生效，中转房间不支持。房主需要启用所需模组并允许传输，客户端在进入房间时下载。

## 是否支持 Linux 与 macOS

Linux 可用发行包中的启动脚本。macOS 目前不提供支持。

## 如何反馈问题

在 [Issues](https://github.com/RWPP-Team/RWPP/issues) 提交时附上启动日志、游戏版本、扩展列表与复现步骤。日志中的扩展标识、版本与失败原因比截图更有助于定位问题。
